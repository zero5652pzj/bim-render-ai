# 变更提案：将登录/注册从手机号改为邮箱

## 概述

当前系统使用手机号作为用户登录和注册的主要标识符。为了提升用户体验和系统可扩展性，计划将认证方式从手机号改为邮箱。

### 当前状态
- 用户使用手机号（+86中国大陆手机号）进行登录和注册
- 系统已支持邮箱字段（profiles表同时有email和phone字段）
- 前端UI使用手机号输入框和验证

### 目标状态
- 用户使用邮箱进行登录和注册
- 保持向后兼容，不影响现有用户数据
- 更新所有相关的UI、验证逻辑和API调用

## 需要修改的范围

### 1. 前端组件
- `src/views/LoginView.vue` - 登录页面
- `src/views/RegisterView.vue` - 注册页面
- 可能需要更新用户菜单或其他显示用户信息的组件

### 2. 状态管理
- `src/stores/auth.ts` - 认证状态管理
  - 移除手机号登录相关方法或保留作为兼容
  - 优化邮箱登录方法

### 3. 类型定义
- `src/lib/supabase.ts` - 数据库类型定义需要确保邮箱字段完整性

### 4. 验证逻辑
- 手机号验证（中国大陆手机号格式）
- 邮箱验证（RFC标准格式）

## 关键决策点

1. **是否保留手机号字段？**
   - 建议：保留phone字段作为可选字段，用于其他功能（如短信通知）

2. **数据库迁移策略**
   - 无需修改数据库结构（email字段已存在）
   - 无需迁移现有数据

3. **向后兼容性**
   - 现有用户可继续使用
   - 新用户只能使用邮箱注册

4. **验证方式**
   - 手机号：移除中国大陆手机号格式验证
   - 邮箱：添加标准RFC邮箱格式验证

## 风险评估

### 低风险
- 数据库结构无需变更
- 现有用户数据不受影响

### 中等风险
- 前端UI大面积修改
- 需要全面测试登录注册流程

### 缓解措施
- 分阶段实施：先修改UI，再更新验证逻辑
- 全面回归测试
- 保留手机号功能作为备选方案（如需要）

   - `loginWithPhonePassword()` → `loginWithPassword()`
   - `registerWithPhone()` → `registerWithEmail()`

   - 占位符：请输入手机号 → 请输入邮箱地址
