# 提案：删除历史聊天记录功能

## 概述

本提案旨在为 bim-render-ai 项目添加完整的删除历史聊天记录功能，包括单个对话删除、消息删除以及批量删除全部历史记录的功能。

## 背景

当前系统已实现基础的聊天功能，包括：
-  conversations 和 messages 表均已支持软删除（is_deleted 字段）
- 已存在 `clear_current_user_history()` 数据库函数
- 前端 stores 已实现基础的删除方法

但缺少用户界面层面对删除功能的访问和控制。

## 目标

1. 为用户提供直观的删除单个对话的界面
2. 为用户提供删除单条消息的界面
3. 提供批量删除全部历史记录的确认机制
4. 实现优雅的用户体验，包括确认对话框和操作反馈
5. 保持软删除机制以确保数据安全

## 范围

### 包含的功能
- 在侧边栏会话列表中添加删除按钮
- 在聊天界面中为每条消息添加删除按钮
- 添加"清空所有历史"功能按钮
- 实现确认对话框防止误操作
- 添加操作成功/失败的提示消息
- 保持现有的软删除机制

### 不包含的功能
- 硬删除（永久删除）
- 恢复已删除对话/消息
- 归档功能
- 搜索已删除记录
- 批量选择删除特定对话

## 设计原则

1. **用户体验优先**：提供清晰的视觉反馈和确认机制
2. **数据安全**：保持软删除机制，防止误删
3. **简单高效**：界面简洁，操作直观
4. **一致性**：与现有 UI 设计风格保持一致
5. **可访问性**：确保所有用户都能方便使用

## 技术考虑

- 利用现有的数据库软删除机制
- 使用前端 Pinia stores 进行状态管理
- 采用 TDesign Vue Next 组件库保持 UI 一致性
- 实现乐观更新以提供即时反馈
- 错误处理和回滚机制

## 成功标准

1. 用户可以轻松删除单个对话
2. 用户可以删除单条消息
3. 用户可以批量删除全部历史记录
4. 所有删除操作都有确认步骤
5. 操作有明确的成功/失败反馈
6. UI 设计与现有界面保持一致
7. 所有操作遵循软删除原则

## 风险与缓解

1. **误删风险**：通过确认对话框和软删除机制缓解
2. **性能影响**：批量删除可能影响性能，考虑分批处理
3. **用户体验中断**：提供清晰的加载状态和反馈
