# 认证功能实现提案

> 提案 ID: `implement-authentication`
> 创建日期: 2026年1月7日
> 状态: 待审核

## 概述

基于 PRD 文档要求，实现完整的用户认证系统，包括用户注册、登录、登出、状态管理等功能。

## 背景

根据《需求确认文档-20260106.md》第5.5节和《技术架构设计文档.md》第4.2节，需要实现基于 Supabase Auth 的认证系统，支持邮箱/密码和手机号两种注册方式，提供完整的用户状态管理和路由守卫功能。

## Why

用户认证是整个系统的基础功能，原因如下：

1. **数据安全**: BIM 模型和对话数据属于用户隐私，需要严格的访问控制
2. **个性化体验**: 用户登录后才能保存和管理自己的会话历史
3. **业务逻辑**: 3D 模型生成、AI 对话等高级功能需要用户身份验证
4. **合规要求**: 工程项目数据需要用户追踪和审计
5. **系统架构**: 后续功能（会话管理、文件上传等）都依赖用户认证系统

没有认证系统，系统无法提供安全的 BIM 数据处理和 AI 建模服务。

## 目标

实现以下核心功能：
1. 用户认证流程（注册、登录、登出）
2. 多种认证方式（邮箱+密码、手机号+密码）
3. Token 管理与自动刷新
4. 用户状态持久化
5. 登录/注册页面 UI
6. 路由守卫与自动登录检查

## 范围

### 包含
- Supabase 认证集成
- 前端认证状态管理（Pinia Store）
- 登录/注册页面组件
- API 认证接口
- 路由守卫
- 用户资料管理

### 不包含
- 3D 模型功能
- 对话功能
- 文件上传功能
- Forge Viewer 集成

## 技术方案

### 前端技术栈
- **认证状态管理**: Pinia Store (`src/stores/auth.ts`)
- **页面组件**: Vue 3 + TDesign (`src/views/LoginView.vue`, `RegisterView.vue`)
- **路由守卫**: Vue Router (`src/router/index.ts`)
- **HTTP 客户端**: Axios + 拦截器

### 后端技术栈
- **认证服务**: Supabase Auth
- **API 接口**: Vercel Functions (`api/auth/*`)
- **数据库**: Supabase PostgreSQL (profiles 表)

### 数据库设计
使用 `public.profiles` 表存储用户扩展信息：
- 关联 `auth.users` 表
- 包含 email, phone, full_name, avatar_url 等字段
- RLS 策略确保用户只能访问自己的数据

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Supabase 认证服务不稳定 | 用户无法登录 | 实现本地缓存和错误重试机制 |
| Token 过期处理不当 | 用户被迫频繁重新登录 | 实现自动 Token 刷新 |
| 路由守卫过于严格 | 影响用户体验 | 允许未登录用户浏览示例卡片 |
| RLS 策略配置错误 | 数据泄露风险 | 严格测试 RLS 策略 |

## 验收标准

1. ✅ 用户可以使用邮箱+密码注册和登录
2. ✅ 用户可以使用手机号+密码注册和登录
3. ✅ 登录后 Token 自动存储到 localStorage
4. ✅ 页面刷新后自动检查登录状态
5. ✅ Token 过期后自动跳转登录页
6. ✅ 登出功能清除所有认证信息
7. ✅ 未登录用户可浏览示例卡片，触发写操作时提示登录
8. ✅ 所有 API 请求自动携带认证 Token
9. ✅ 用户资料正确加载和显示
10. ✅ 密码强度验证和错误提示完善
