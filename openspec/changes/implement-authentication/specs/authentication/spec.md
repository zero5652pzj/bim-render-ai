# 认证功能规范

## 概述

本文档定义了 AI+BIM 建模网站的用户认证系统，包括注册、登录、登出、Token 管理等核心功能。

## 依赖项

- [Supabase Auth](https://supabase.com/docs/guides/auth)
- [Pinia 状态管理](https://pinia.vuejs.org/)
- [Vue Router 路由守卫](https://router.vuejs.org/)

## ADDED Requirements

### Requirement: 用户注册功能

用户 **SHALL** 能够使用邮箱或手机号进行注册。

#### Scenario: 邮箱注册
- 给定 用户访问注册页面
- 当 用户填写邮箱、密码、昵称并提交
- 那么 系统创建新用户账号
- 并且 发送邮箱验证链接（如果启用）
- 并且 自动登录并跳转到主页

#### Scenario: 手机号注册
- 给定 用户选择手机号注册方式
- 当 用户填写手机号、密码、昵称并提交
- 那么 系统创建新用户账号
- 并且 可以通过手机号登录

#### Scenario: 注册失败处理
- 给定 用户提交重复的邮箱或手机号
- 当 系统检测到账号已存在
- 那么 显示错误提示"该邮箱/手机号已被注册"
- 并且 不创建新账号

#### Scenario: 密码强度验证
- 给定 用户输入密码
- 当 密码少于 6 位或过于简单
- 那么 显示错误提示"密码至少 6 位"
- 并且 不允许提交

### Requirement: 用户登录功能

用户 **SHALL** 能够使用注册的邮箱/手机号和密码登录。

#### Scenario: 邮箱登录
- 给定 用户访问登录页面
- 当 用户输入正确的邮箱和密码
- 那么 系统验证凭据
- 并且 登录成功，存储 Token
- 并且 跳转到主页，加载用户会话

#### Scenario: 手机号登录
- 给定 用户选择手机号登录
- 当 用户输入正确的手机号和密码
- 那么 系统验证凭据
- 并且 登录成功，存储 Token

#### Scenario: 登录失败处理
- 给定 用户输入错误的密码
- 当 系统验证失败
- 那么 显示错误提示"邮箱/手机号或密码错误"
- 并且 不跳转，保持在登录页

#### Scenario: 自动登录
- 给定 用户已登录过且 Token 有效
- 当 用户访问网站
- 那么 自动验证 Token 有效性
- 并且 直接登录，无需输入密码

### Requirement: 登出功能

用户 **SHALL** 能够安全登出，清除所有认证信息。

#### Scenario: 手动登出
- 给定 用户已登录
- 当 用户点击登出按钮
- 那么 清除 localStorage 中的 Token
- 并且 调用 Supabase 登出 API
- 并且 跳转到登录页
- 并且 清空用户状态

#### Scenario: Token 过期登出
- 给定 用户已登录但 Token 已过期
- 当 用户发起 API 请求
- 那么 服务器返回 401 状态码
- 那么 客户端检测到 Token 过期
- 那么 清除认证信息
- 那么 跳转到登录页并提示"登录已过期"

### Requirement: Token 管理

系统 **MUST** 实现 JWT Token 的存储、刷新、验证机制。

#### Scenario: Token 存储
- 给定 用户登录成功
- 当 系统获取到 JWT Token
- 那么 将 Token 存储到 localStorage
- 并且 设置 Token 过期时间

#### Scenario: Token 自动刷新
- 给定 用户保持活跃状态
- 当 Token 即将过期（如剩余 10 分钟）
- 那么 Supabase SDK 自动刷新 Token
- 并且 更新 localStorage 中的 Token

#### Scenario: Token 验证
- 给定 用户发起 API 请求
- 当 请求头包含 Authorization: Bearer Token
- 那么 服务器验证 Token 有效性
- 并且 验证通过则处理请求
- 并且 验证失败则返回 401

#### Scenario: Token 过期处理
- 给定 用户发起 API 请求
- 当 Token 已过期
- 那么 服务器返回 401 Unauthorized
- 那么 客户端清除本地 Token
- 那么 跳转到登录页

### Requirement: 认证状态管理

系统 **MUST** 实现前端认证状态的持久化和同步。

#### Scenario: 页面加载时检查认证
- 给定 用户打开网站
- 当 页面加载完成
- 那么 检查 localStorage 中是否有 Token
- 那么 验证 Token 有效性
- 那么 同步用户状态到 Pinia Store

#### Scenario: 认证状态监听
- 给定 用户已登录
- 当 Supabase Auth 状态发生变化（如登出）
- 那么 自动更新 Pinia Store 中的用户状态
- 那么 UI 自动响应状态变化

#### Scenario: 认证失败清理
- 给定 用户认证失败或 Token 验证失败
- 当 检测到认证问题
- 那么 清除 Pinia Store 中的用户状态
- 那么 清除 localStorage 中的 Token
- 那么 跳转到登录页

### Requirement: 路由守卫

系统 **MUST** 根据认证状态控制页面访问权限。

#### Scenario: 未登录访问受保护页面
- 给定 用户未登录
- 当 用户尝试访问主页
- 那么 允许访问（未登录也可浏览示例卡片）
- 当 用户尝试进行写操作（创建会话、发送消息）
- 那么 提示用户登录
- 并且 登录成功后继续之前操作

#### Scenario: 已登录访问登录页
- 给定 用户已登录
- 当 用户访问 /login 或 /register 页面
- 那么 自动跳转到主页
- 并且 不显示登录表单

#### Scenario: 路由权限检查
- 给定 用户发起页面跳转
- 当 目标页面需要认证（requiresAuth: true）
- 那么 检查用户是否已登录
- 如果未登录，跳转到登录页
- 如果已登录，允许访问

### Requirement: 错误处理与用户提示

系统 **MUST** 实现完善的错误处理和用户反馈机制。

#### Scenario: 网络错误处理
- 给定 用户尝试登录
- 当 发生网络连接错误
- 那么 显示错误提示"网络连接失败，请检查网络设置"
- 并且 提供重试按钮

#### Scenario: 服务器错误处理
- 给定 用户发起认证请求
- 当 服务器返回 500 错误
- 那么 显示错误提示"服务器繁忙，请稍后重试"
- 并且 记录错误日志

#### Scenario: 验证码发送（预留）
- 给定 用户选择手机号登录
- 当 用户点击"获取验证码"
- 那么 发送 6 位数字验证码到手机
- 并且 显示"验证码已发送"
- 并且 60 秒后可重新发送

#### Scenario: 密码重置（预留）
- 给定 用户忘记密码
- 当 用户点击"忘记密码"
- 那么 发送密码重置邮件
- 并且 提示"请检查邮箱并点击重置链接"

## 安全要求

### S1: 密码安全
- 密码必须至少 6 位
- 建议包含字母和数字
- 不在前端日志中输出密码
- 不在网络中明文传输密码

### S2: Token 安全
- 使用 HTTPS 传输所有认证请求
- Token 仅存储在客户端 localStorage
- Token 包含过期时间
- 实现 Token 自动刷新机制

### S3: 数据保护
- 用户敏感信息（密码）不存储在 profiles 表
- profiles 表仅存储公开信息
- 启用 RLS 策略，确保用户只能访问自己的数据
- 所有 API 请求需要认证（除示例卡片读取）

### S4: 会话管理
- 单一用户只能在一个设备上活跃登录（可选）
- 检测到异地登录时提示用户
- 支持手动登出其他设备（预留功能）

## 性能要求

### P1: 响应时间
- 登录请求响应时间 < 2 秒
- Token 验证响应时间 < 500ms
- 页面加载时认证检查 < 1 秒

### P2: 可用性
- 认证服务可用性 > 99.5%
- 支持离线模式（仅浏览示例卡片）
- 网络恢复后自动重试认证

## 兼容性要求

### C1: 浏览器支持
- Chrome ≥ 84
- Firefox ≥ 83
- Safari ≥ 14.1
- Edge ≥ 84

### C2: 移动端支持
- 响应式设计，适配移动端
- 支持移动端键盘类型（邮箱键盘、数字键盘）
- 支持 Touch ID / Face ID（预留）

## 日志与监控

### L1: 认证日志
记录以下事件：
- 用户登录/登出
- 注册成功/失败
- Token 刷新
- 认证失败（记录到服务器）

### L2: 性能监控
- 监控认证 API 响应时间
- 监控 Token 刷新成功率
- 监控登录成功率

### L3: 错误追踪
- 捕获认证相关错误
- 关联用户 ID（如果已登录）
- 发送到错误监控服务
