## Requirements
### Requirement: 用户注册功能

用户 **SHALL** 能够使用邮箱或手机号进行注册。

#### Scenario: 邮箱注册
- 给定 用户访问注册页面
- 当 用户填写邮箱、密码、昵称并提交
- 那么 系统创建新用户账号
- 并且 发送邮箱验证链接（如果启用）
- 并且 自动登录并跳转到主页

#### Scenario: 手机号注册
- 给定 用户选择手机号注册方式
- 当 用户填写手机号、密码、昵称并提交
- 那么 系统创建新用户账号
- 并且 可以通过手机号登录

#### Scenario: 注册失败处理
- 给定 用户提交重复的邮箱或手机号
- 当 系统检测到账号已存在
- 那么 显示错误提示"该邮箱/手机号已被注册"
- 并且 不创建新账号

#### Scenario: 密码强度验证
- 给定 用户输入密码
- 当 密码少于 6 位或过于简单
- 那么 显示错误提示"密码至少 6 位"
- 并且 不允许提交

### Requirement: 用户登录功能

用户 **SHALL** 能够使用注册的邮箱/手机号和密码登录。

#### Scenario: 邮箱登录
- 给定 用户访问登录页面
- 当 用户输入正确的邮箱和密码
- 那么 系统验证凭据
- 并且 登录成功，存储 Token
- 并且 跳转到主页，加载用户会话

#### Scenario: 手机号登录
- 给定 用户选择手机号登录
- 当 用户输入正确的手机号和密码
- 那么 系统验证凭据
- 并且 登录成功，存储 Token

#### Scenario: 登录失败处理
- 给定 用户输入错误的密码
- 当 系统验证失败
- 那么 显示错误提示"邮箱/手机号或密码错误"
- 并且 不跳转，保持在登录页

#### Scenario: 自动登录
- 给定 用户已登录过且 Token 有效
- 当 用户访问网站
- 那么 自动验证 Token 有效性
- 并且 直接登录，无需输入密码

### Requirement: 登出功能

用户 **SHALL** 能够安全登出，清除所有认证信息。

#### Scenario: 手动登出
- 给定 用户已登录
- 当 用户点击登出按钮
- 那么 清除 localStorage 中的 Token
- 并且 调用 Supabase 登出 API
- 并且 跳转到登录页
- 并且 清空用户状态

#### Scenario: Token 过期登出
- 给定 用户已登录但 Token 已过期
- 当 用户发起 API 请求
- 那么 服务器返回 401 状态码
- 那么 客户端检测到 Token 过期
- 那么 清除认证信息
- 那么 跳转到登录页并提示"登录已过期"

### Requirement: Token 管理

系统 **MUST** 实现 JWT Token 的存储、刷新、验证机制。

#### Scenario: Token 存储
- 给定 用户登录成功
- 当 系统获取到 JWT Token
- 那么 将 Token 存储到 localStorage
- 并且 设置 Token 过期时间

#### Scenario: Token 自动刷新
- 给定 用户保持活跃状态
- 当 Token 即将过期（如剩余 10 分钟）
- 那么 Supabase SDK 自动刷新 Token
- 并且 更新 localStorage 中的 Token

#### Scenario: Token 验证
- 给定 用户发起 API 请求
- 当 请求头包含 Authorization: Bearer Token
- 那么 服务器验证 Token 有效性
- 并且 验证通过则处理请求
- 并且 验证失败则返回 401

#### Scenario: Token 过期处理
- 给定 用户发起 API 请求
- 当 Token 已过期
- 那么 服务器返回 401 Unauthorized
- 那么 客户端清除本地 Token
- 那么 跳转到登录页

### Requirement: 认证状态管理

系统 **MUST** 实现前端认证状态的持久化和同步。

#### Scenario: 页面加载时检查认证
- 给定 用户打开网站
- 当 页面加载完成
- 那么 检查 localStorage 中是否有 Token
- 那么 验证 Token 有效性
- 那么 同步用户状态到 Pinia Store

#### Scenario: 认证状态监听
- 给定 用户已登录
- 当 Supabase Auth 状态发生变化（如登出）
- 那么 自动更新 Pinia Store 中的用户状态
- 那么 UI 自动响应状态变化

#### Scenario: 认证失败清理
- 给定 用户认证失败或 Token 验证失败
- 当 检测到认证问题
- 那么 清除 Pinia Store 中的用户状态
- 那么 清除 localStorage 中的 Token
- 那么 跳转到登录页

#### Scenario: 主页用户状态显示
- 给定 用户访问主页
- 当 用户未登录时
- 那么 侧边栏底部显示"登录"按钮
- 并且 点击按钮跳转到登录页
- 当 用户已登录时
- 那么 侧边栏底部显示用户名和头像
- 并且 点击后展开下拉菜单（个人资料、设置、退出登录）

### Requirement: 路由守卫

系统 **MUST** 根据认证状态控制页面访问权限。

#### Scenario: 未登录访问受保护页面
- 给定 用户未登录
- 当 用户尝试访问主页
- 那么 允许访问（未登录也可浏览示例卡片）
- 当 用户尝试进行写操作（创建会话、发送消息）
- 那么 提示用户登录
- 并且 登录成功后继续之前操作

#### Scenario: 已登录访问登录页
- 给定 用户已登录
- 当 用户访问 /login 或 /register 页面
- 那么 自动跳转到主页
- 并且 不显示登录表单

#### Scenario: 路由权限检查
- 给定 用户发起页面跳转
- 当 目标页面需要认证（requiresAuth: true）
- 那么 检查用户是否已登录
- 如果未登录，跳转到登录页
- 如果已登录，允许访问

### Requirement: 错误处理与用户提示

系统 **MUST** 实现完善的错误处理和用户反馈机制。

#### Scenario: 网络错误处理
- 给定 用户尝试登录
- 当 发生网络连接错误
- 那么 显示错误提示"网络连接失败，请检查网络设置"
- 并且 提供重试按钮

#### Scenario: 服务器错误处理
- 给定 用户发起认证请求
- 当 服务器返回 500 错误
- 那么 显示错误提示"服务器繁忙，请稍后重试"
- 并且 记录错误日志

#### Scenario: 验证码发送（预留）
- 给定 用户选择手机号登录
- 当 用户点击"获取验证码"
- 那么 发送 6 位数字验证码到手机
- 并且 显示"验证码已发送"
- 并且 60 秒后可重新发送

#### Scenario: 密码重置（预留）
- 给定 用户忘记密码
- 当 用户点击"忘记密码"
- 那么 发送密码重置邮件
- 并且 提示"请检查邮箱并点击重置链接"
